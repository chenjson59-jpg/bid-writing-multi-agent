# 规格：删除文档时级联清理 Chroma 向量（T-016）

## 1. 用户场景与业务目标

`DELETE /api/documents/{doc_id}` 目前只删除 `upload/parsed/{doc_id}` 解析目录与
`upload/files/{doc_id}_*` 上传原件，不清理 Chroma 中的片段；按保留期执行的
`scripts/cleanup.py` 同样只删磁盘目录。文档删除后其向量片段成为孤儿数据：
既占存储，又可能在后续不带 `doc_id` 过滤的检索中被召回，污染生成依据，违反
AGENTS.md 第 5.3 节「删除文档时同步清理对应向量片段，避免孤儿向量」。

目标：提供一个可复用的向量级联删除函数，接口删除与保留期清理两条路径都接入；
向量库异常时显式失败、保留磁盘文件以便重试，禁止静默成功。

## 2. 输入、输出与副作用

- 新增 `src/vectorstore/ingest.py::delete_document_vectors(doc_id, *, client=None) -> int`：
  - 输入：16 位 hex `doc_id`；`client` 仅供测试注入 Fake，生产默认取进程单例
    `get_client()`；
  - 输出：实际删除的片段总数（两个集合相加）；集合不存在或无匹配片段时返回 `0`，
    属幂等成功；
  - 副作用：对已存在的 `tender_announcement`、`tender_document` 两个已知集合，
    删除 metadata 中 `doc_id` 匹配的片段；不创建任何集合（禁止走
    `get_or_create_collection`，删除路径凭空建集合属于副作用污染）。
- `DELETE /api/documents/{doc_id}` 响应契约不变：成功仍返回 `{"deleted": true}`；
  新增失败语义：向量清理抛 `IngestError` 时返回 **503**，解析目录与原件全部保留。
- `scripts/cleanup.py`：删除 `PARSED_DIR` 下文档目录前先清向量；`BIDS_DIR` 下的
  标书产物不对应向量，不调用；`--dry-run` 不产生任何向量侧副作用。
- 无数据库表结构、无请求/响应 Schema 字段变化。

## 3. 正常、异常与边界路径

- 正常：文档片段分布在两个集合中，两个集合内该 `doc_id` 的片段全部删除，其他
  `doc_id` 的片段不受影响，返回删除条数之和。
- 集合缺失：从未入库的新环境 `list_collections()` 不含已知集合名，跳过并返回 0，
  不报错、不建集合。
- 集合存在但无该文档片段：`get(where=...)` 返回空 id 列表，跳过删除，计入 0。
- 重复删除：接口侧 404 存在性检查保持在前；即便绕过检查再次调用向量函数，
  第二次返回 0，整体仍幂等。
- 向量库异常（持久化目录不可用、client 初始化/查询/删除抛错）：
  - 向量函数把底层异常包装为带 `doc_id` 上下文的 `IngestError`，不吞错；
  - 接口返回 503 且**先于**磁盘删除执行，文件保留，用户重试即可完成完整删除；
  - 清理脚本跳过该文档的目录删除、打印失败信息，继续处理其余目标，进程以非零
    退出码结束，避免留下「目录已删、向量残留」的不一致。
- 非法 `doc_id`：仍由路径参数正则拦截返回 422，不进入删除逻辑。

## 4. 权限、安全与一致性

- 不引入新的鉴权面，沿用删除端点现有令牌校验。
- 只按 metadata `doc_id` 精确删除，不支持任意 where 条件，避免误删跨文档片段。
- 删除顺序固定为「404 检查 → 清向量 → 删磁盘文件」：向量失败时磁盘不动；
  向量成功后磁盘删除若失败，重试时向量函数返回 0 幂等成功，不产生新的不一致窗口。
- 测试一律注入 Fake client / monkeypatch 接口函数，禁止真实 Chroma、嵌入模型与
  网络；不得在工作区生成 `chroma_db/` 测试数据。

## 5. 兼容性与验收标准

- 接口成功响应体、404/422 语义保持不变；新增 503 为依赖失败的显式表达，与资料
  删除端点数据库不可用时返回 503 的既有约定一致。
- 验收标准：
  1. 向量函数对「双集合命中、单集合命中、集合缺失、零片段、底层异常」五种路径
     均有离线 Fake 单测，且断言只删目标 `doc_id`、返回值准确、异常转为
     `IngestError`；
  2. 接口测试断言删除时调用了向量函数且参数正确；向量函数失败时返回 503、
     解析目录与原件均保留；重复删除 404、非法 id 422 行为不变；
  3. 清理脚本测试覆盖正常清理（解析目录触发向量清理、标书产物不触发）、
     dry-run 无副作用、向量失败时目录保留且退出码非零；
  4. `docs/api-contract.md`（§5.3、§7.6 补登 DELETE 端点）、`docs/tech-decisions.md`
     §3.5、`README.md` 同步描述级联清理与 503 语义；
  5. `uv run ruff check api src tests scripts` 与 `uv run pytest -q` 全绿，
     且测试过程不生成真实 `chroma_db/` 数据。
