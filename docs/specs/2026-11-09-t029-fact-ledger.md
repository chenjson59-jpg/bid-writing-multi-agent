# 规格：全局事实表与数字口径一致性检查（T-029）

> 状态：已定稿（2026-11-09）。基线代码：main `650457f`（389 passed）。
> 关联规则：AGENTS.md §5.1（禁虚构）、§5.4（确定性规则与模型评分分离）。

## 1. 用户场景与业务目标

投标文件中工期、投标保证金、投标有效期、预算/最高限价、项目名称、项目编号
属于**强约束事实**：同一事实在不同章节出现不同写法属于废标高风险（例如
37 章里工期同时出现 180 天与 200 天）。当前系统只有章节级 LLM 语义评审与
5 个确定性规则码（引用 3 项、报价禁令、占位符），没有跨章节的事实口径校验。

目标（本期只做两件事，不新增任何 LLM 调用）：

1. 从既有 `TenderDocument` 抽取结果**确定性构建**全局事实表 `FactLedger`，
   每条事实带类型、归一值、单位、原文片段与来源字段，随产物落盘 `facts.json`；
2. 在章节确定性规则检查中新增 `FACT_MISMATCH` 规则码：正文锚点表述与事实表
   冲突即报错，与 LLM Reviewer 评分完全分离，前端经既有 rule_check 通道泛化展示。

非目标（显式排除）：

- 不新增 LLM 调用、不改 Writer/Reviewer/Reviser 提示词（prompt 注入另立任务）；
- 不新建数据库表、不引入 Alembic（沿用产物 JSON + 原子替换模式，绕开 T-023）；
- 不做事实表人工编辑 UI（预留 `reviewed` 字段，编辑能力后续立项）；
- 不做月↔天、工作日↔自然日等含业务假设的自动换算。

## 2. 事实模型

### 2.1 Fact 数据结构

```python
@dataclass
class Fact:
    fact_type: str   # budget | deposit | duration | validity | project_name | tender_no
    label: str       # 命中的中文锚点，如「工期」「投标保证金」；扁平字段取字段中文名
    value: str       # 数值型：归一到标准单位后的十进制字符串（金额量化 2 位小数）；字符串型：原文
    unit: str        # 标准单位：元 | 天 | 工作日 | 月 | ""（字符串型）
    raw_text: str    # 命中文本原文（截断 200 字符）
    source: str      # 来源标识，如 basic.budget_amount、contract_highlights[2]
    confidence: float  # 扁平结构化字段 1.0；规则文本抽取 0.8
    reviewed: bool = False  # 预留：人工核对标记，本期恒 False
```

### 2.2 事实类型与锚点（抽取端与校验端共用同一套正则，同尺子度量）

| fact_type | 锚点（长词在前，左优先） | 取值模式 | 标准单位 |
|---|---|---|---|
| deposit | 投标保证金、保证金 | 数字 +（万元\|元） | 元 |
| budget | 预算金额、最高限价、招标控制价、控制价、预算 | 数字 +（万元\|元） | 元 |
| duration | 工期、服务期限、服务期、供货期限、供货期、交付期限、交付期 | 数字 +（日历天\|工作日\|天\|个月\|月） | 天/工作日/月 |
| validity | 投标有效期、有效期 | 数字 +（日历天\|工作日\|天） | 天/工作日 |
| project_name | 项目名称、工程名称 | 标签后 4–40 字非标点串 | "" |
| tender_no | 项目编号、招标编号、采购编号 | 标签后 4–40 位字母数字及 `-_` | "" |

统一窗口形式：`锚点[^。；;\n]{0,12}?数字\s*单位`（非贪婪，不跨句号/分号/换行）。

### 2.3 来源字段

- 扁平字段：`budget_amount`（可解析为金额时入库，不可解析跳过）、`project_name`、
  `tender_no`（非空即入库，confidence=1.0，source 为 `basic.<field>`）；
- 文本字段（confidence=0.8）：`contract_highlights`、`technical_requirements`、
  `service_requirements`、`preliminary_review`、`qualifications[].requirement`，
  source 带数组下标，如 `contract_highlights[2]`；
- 同 `(fact_type, value, unit)` 去重（保留首次出现的 raw_text/source）；
- 同类型冲突事实全部保留，不丢弃（校验时任一匹配即通过，见 §4）。

### 2.4 单位归一

- 金额：万元 ×10000 → 元，`decimal.Decimal` 计算并量化到 0.01，禁止 float 直比；
- 工期：日历天/天 → 天；工作日独立保留；个月/月 → 月；
- 有效期：日历天/天 → 天；工作日独立保留；
- 仅同标准单位之间可比；跨单位（月 vs 天、工作日 vs 天）跳过，不臆造错误。

## 4. 校验语义与误报控制

1. 数值型：正文每个锚点命中得到 `(type, 值, 单位)`，单位归一后与 ledger
   同类型事实比较；该类型无事实 → 跳过；与任一事实相等 → 通过；与全部事实
   都不等 → `FACT_MISMATCH`，message 含锚点、正文值与事实表值；
2. 字符串型：标签命中后去空白比较，完全相等通过；双向子串且短串长度 ≥
   长串 60% 视为简称通过；否则报错；
3. 命中窗口内含 `【待填写` 占位符 → 跳过该命中（人工待填不判错）；
4. 跨标准单位（月/天、工作日/天）→ 跳过；
5. 金额类表述可能同时命中既有 `QUOTE_FORBIDDEN`，两码各表一事，允许并存；
6. 正则只在锚点短窗口内取值，不做全文数字扫描，从机制上限制误报面。

## 5. 正常 / 异常 / 边界路径

- 正常：tender 含扁平字段与文本事实 → ledger 非空；正文口径一致 → 无新错误；
  正文冲突 → 对应章节 rule_check 出现 FACT_MISMATCH、`passed=false`；
- 空 tender / 所有字段为空 → 空 ledger，全部检查跳过，与现状完全一致；
- `budget_amount` 为纯散文无法解析数字 → 跳过该条，不抛异常；
- 旧产物反序列化（无 facts.json、report 无 fact_check_summary）→ 默认空值，
  `from_dict` 容忍缺键与未知键；
- eval 评测路径（`writing_runner` 直接调 pipeline 函数且不传 ledger）→
  不构建事实表，冻结基线（调用数/token/规则数/覆盖率）保持不变；
- `FACT_MISMATCH` 不加入 `eval/harness/writing_metrics.py` 的 `RULE_CODES`
  冻结键集合（eval 样本不构建 ledger，加入无对应样本覆盖）。

## 6. 权限与安全

- 纯本地确定性计算，无新网络出口、无新文件根目录；facts.json 写入既有
